# CheckIT AI — 스마트 외출 준비물 점검 MVP

웹앱 화면 배치, 시각 스타일, 상태별 안내와 단계별 적용 계획은 [웹앱 화면 설계](UI_DESIGN.md)에 정리했습니다. 이 문서는 설계이며 현재 구현 상태와 구분합니다.

## 서비스 목표 및 구현 요구사항

CheckIT은 웹앱을 실행한 뒤 지정된 검사 구역에 준비물을 놓으면, 웹캠으로 물건을 실시간 인식하여 외출 준비 여부를 확인하는 서비스입니다. 결과는 웹앱 체크리스트와 Arduino의 16×2 LCD에 함께 표시합니다.

**아래는 목표 요구사항입니다. 구현 여부는 ‘현재 구현 상태’와 VALIDATION.md에서 구분합니다.** 실행 및 연결 안내는 이 문서의 후반부에 유지합니다.

### 서비스 이용 흐름

1. 웹앱에서 사용자를 직접 선택하고 준비물 목록과 날씨 설정을 불러옵니다.
2. 카메라 사용 권한을 허용하면 별도의 ‘검사 시작’ 버튼 없이 실시간 인식을 시작합니다.
3. 카메라 화면에서 검사 구역을 설정하거나 확인하고, 해당 구역에 물건을 놓습니다.
4. 오늘의 준비물 목록과 구역 안에서 인식된 물건을 비교합니다.
5. 확인된 항목은 웹앱에서 체크와 취소선으로 표시하고 LCD의 미완료 목록에서 제거합니다.
6. 모든 준비물이 확인되면 웹앱과 LCD에 준비 완료 메시지를 표시합니다.

### 웹앱 및 지정 구역 기반 실시간 인식

- 웹앱에서 카메라를 사용하는 동안 실시간 인식을 수행하며, 사용자가 중지할 수 있습니다.
- 최초 사용 시 브라우저의 카메라 권한 승인이 필요합니다.
- 검사 구역 경계를 영상 위에 표시하여 물건을 놓을 위치를 안내합니다.
- 지정 구역 안의 물건만 검사에 반영하고 구역 밖의 물건은 반영하지 않습니다.
- 사람의 통과나 얼굴을 검사 시작 조건으로 사용하지 않습니다.
- 별도의 상시 카메라 프로그램, 사람 감지에 따른 브라우저 자동 실행, 얼굴 등록·인식 기능은 사용하지 않습니다.

### 체크리스트 화면 및 확인 상태

수동 확인 버튼은 네모 체크박스로 변경합니다. 자동 인식과 사용자 체크를 동일한 준비물 상태에 반영합니다.

| 상태 | 웹앱 표시 |
|---|---|
| 미확인 | 빈 체크박스와 준비물 이름 |
| 확인 완료 | 체크된 체크박스와 이름의 취소선 |
| 오늘만 제외 | 당일 검사 대상에서 제외 |
| 전체 확인 완료 | ‘준비 완료’ 메시지 |

표시 예시:

- [ ] 물병
- [x] ~~책~~
- [ ] 우산

- 자동 인식이 어려운 물건은 사용자가 체크박스로 직접 확인할 수 있습니다.
- 물건이 안정적으로 인식되면 완료 상태를 유지합니다. 확인한 물건을 가방에 넣어 구역에서 사라져도 체크를 해제하지 않습니다.
- 사용자가 체크를 해제하면 미확인 상태로 돌아가며 LCD에도 다시 반영합니다.
- 수동 해제 직후 같은 물건이 계속 보이면 즉시 다시 체크되지 않도록 재확인 기준을 정합니다.
- 새 검사를 시작하면 이전 확인 상태를 초기화합니다.
- 인식되지 않은 물건은 ‘없음’이 아니라 ‘미확인’으로 표시합니다.

### 사용자별 준비물 관리

- 얼굴 인식 대신 웹앱에서 사용자를 직접 선택합니다.
- 기본 목록은 물병·책·우산이며 사용자가 준비물을 추가하거나 삭제할 수 있습니다.
- 목록에서 삭제하지 않고 오늘만 검사 대상에서 제외할 수 있습니다.
- 오늘만 제외한 항목은 다음 날 검사 대상에 다시 포함합니다.
- 사용자별 목록과 설정을 저장합니다.

### 기본 물건 및 개인 물건 사진 등록

| 구분 | 목적 | 구현 방향 |
|---|---|---|
| 기본 물건 | 물병·책·우산 등 종류 확인 | YOLO 기반 인식 |
| 개인 물건 | 사용자가 등록한 특정 물건 확인 | 등록 사진 비교 또는 추가 학습 |

- 기본 인식 범위는 사용하는 모델이 지원하는 클래스에 맞춰 확정합니다.
- 사용자는 개인 물건의 이름과 여러 각도·거리에서 촬영한 사진을 등록할 수 있습니다.
- 등록 후 실제 검사 구역에서 인식되는지 확인하는 단계를 제공합니다.
- 등록한 물건과 사진을 삭제할 수 있습니다.
- 목록 추가와 자동 인식 지원은 별개입니다. 사진 등록만으로 기존 YOLO가 새로운 물건을 자동 학습하지는 않습니다.
- 개인 물건 인식 방식은 조명·각도·가려짐에 따른 정확도를 검증한 후 확정합니다.

### 기상청 API와 우산 자동 추가

- 사용자가 설정한 지역의 날씨를 기상청 API로 조회합니다.
- 사용자는 우산 자동 추가 기능을 켜거나 끄고, 날씨 조회 지역과 비 판단 기준을 설정할 수 있습니다.
- 현재 강수 또는 당일 비 예보 등 설정한 조건에 해당하면 오늘의 검사 목록에 우산을 추가합니다.
- 이미 포함된 우산은 중복 추가하지 않습니다.
- 자동 추가된 우산도 오늘만 제외할 수 있으며, 날씨가 갱신되어도 당일에는 다시 추가하지 않습니다.
- 날씨 조회 실패 시 실패 상태를 안내하며, 이를 비가 오지 않는 것으로 처리하지 않습니다.

### Arduino 16×2 LCD 표시

- LCD는 16열 × 2행이며, 한 줄에 하나씩 **최대 2개의 미완료 준비물**을 표시합니다.
- 전체 준비물 수는 2개로 제한하지 않습니다. 3개 이상이면 목록 순서대로 앞의 2개를 표시합니다.
- 항목이 완료되면 화면에서 제거하고 다음 미완료 항목을 빈 줄에 표시합니다.
- 체크 해제 시 해당 물건을 미완료 목록에 다시 포함하고 목록 순서에 따라 화면을 갱신합니다.
- 오늘 검사에서 제외한 항목은 표시하지 않습니다.
- 모든 항목이 완료되면 `READY!` / `ALL CHECKED`를 표시합니다. 처음부터 검사 대상이 없으면 별도로 `NO ITEMS`를 표시합니다.
- 한 줄에 들어가는 짧은 표시명을 사용합니다. 현재 LCD의 ASCII 표시를 기준으로 영문 이름을 사용하며, 웹앱은 한글 이름을 표시합니다.
- 웹앱에서 준비물 목록과 확인 상태를 Arduino로 전송합니다. 목록 변경 때마다 펌웨어를 다시 업로드하는 방식은 사용하지 않습니다.
- 장치 연결 실패와 재연결 시 상태 동기화 방식을 제공합니다.

물병·책·우산이 등록된 경우의 LCD 표시 예시:

```text
처음             물병 완료         모두 완료
+----------------+ +----------------+ +----------------+
|BOTTLE          | |BOOK            | |READY!          |
|BOOK            | |UMBRELLA        | |ALL CHECKED     |
+----------------+ +----------------+ +----------------+
```

### 목표 시스템 구성

| 구성 요소 | 역할 |
|---|---|
| 웹캠 | 지정 검사 구역 영상 입력 |
| 웹앱 | 사용자 선택, 구역 설정, 준비물 관리, 체크리스트 표시 |
| 인식 모듈 | YOLO 탐지, 구역 필터링, 개인 물건 인식 |
| 데이터 저장소 | 사용자별 목록, 설정, 개인 물건 사진 저장 |
| 기상청 API 연동 모듈 | 날씨 조회와 우산 추가 조건 판단 |
| Arduino 통신 모듈 | 목록 및 확인 상태 전송 |
| Arduino와 16×2 LCD | 미완료 항목 최대 2개와 완료 메시지 표시 |

카메라 작동 상태와 중지 기능을 제공하고 검사 영상은 기본적으로 저장하지 않습니다. 개인 물건 등록 사진은 사용자 요청으로 저장하며 삭제 기능을 제공합니다. 얼굴 데이터는 수집하지 않습니다.

### 구현 단계 및 결정할 사항

1. 지정 구역 실시간 인식과 체크박스·취소선 UI, 확인 상태 유지 및 초기화
2. 사용자별 준비물 추가·삭제·오늘만 제외, 목록과 설정 저장
3. 기상청 API 연동 및 우산 자동 추가 설정
4. 16×2 LCD의 목록 전송·완료 항목 제거·재연결 동기화
5. 개인 물건 사진 등록 및 인식 정확도 검증

구현 전에 구역 경계 판정, 연속 인식 시간·신뢰도, 수동 해제 후 재확인 조건, 지원 클래스, 개인 물건 인식 방식, 날씨 조회 시간 범위, 날짜 변경 기준, 새 검사 초기화 시점, LCD 표시명과 통신 규약을 확정합니다. 인식 모듈의 실행 위치도 구현 환경에 맞춰 결정합니다.

## 현재 구현 상태 — 9/9단계 코드 구현 완료

브라우저 카메라 영상, 지정 구역 필터링과 연속 인식, 체크리스트, 사용자별 관리, LCD 목록 동기화, 날씨·우산 자동 추가와 개인 물건 사진 비교를 구현했습니다. 개인 물건 비교는 글자·무늬가 있는 물건을 대상으로 하는 시험 기능이며 실제 사용 환경에서의 인식률 확인이 필요합니다. Arduino 실물 검증은 하드웨어 설계 이후에 진행합니다.

### 개인 물건 사진 등록·인식

1. 메인 화면 아래 ‘내 물건 등록·관리’를 엽니다. 이름, LCD 영문 이름과 등록 사진 1~8장을 입력합니다. 사진은 장당 10MB·2,500만 픽셀 이하이며 글자·무늬가 보이도록 물건 위주로 촬영하세요.
2. ‘관리할 개인 물건’을 선택하고 실제 검사 구역에 놓은 물건의 다른 사진으로 인식 시험을 합니다. 사진 업로드와 카메라 촬영을 사용할 수 있습니다.
3. 시험을 통과한 뒤 ‘자동 확인 켜기’를 누르면 사진 분석과 실시간 인식에 함께 반영합니다. 활성화 전에는 직접 체크로 확인합니다.
4. 자동 확인을 끄거나 사진을 추가·삭제할 수 있습니다. 사진 변경 후에는 다시 시험을 통과해야 자동 확인을 켤 수 있습니다. 물건 삭제 시 등록 사진도 삭제합니다.

비교 방식은 OpenCV ORB 특징점과 RANSAC 원근 변환 검증입니다. 단순한 색상 유사도나 YOLO 추가 학습이 아닙니다. 책 표지·인쇄된 소품 등 특징이 있는 면에 적합하며, 무지 물병·반사 물체·심한 가림·큰 시점 변화는 잘 인식되지 않을 수 있습니다. 같은 위치가 여러 등록 물건과 일치하면 모두 미확인으로 남깁니다. 시험 통과는 다른 환경의 정확도를 보장하지 않으므로 다른 각도·조명과 다른 물건에서도 확인하세요.

활성화한 물건은 기존 검사 구역·연속 인식·수동 해제 보호 규칙을 따릅니다. 시험은 준비물 체크 결과를 자동으로 바꾸지 않습니다. 등록 사진은 사용자별 SQLite에 크기를 줄인 JPEG로 저장하고 촬영 메타데이터는 보존하지 않습니다. 검사 영상·시험 장면은 별도 저장하지 않습니다.

구현 참고: [OpenCV 특징점 매칭](https://docs.opencv.org/4.x/dc/dc3/tutorial_py_matcher.html), [특징점과 원근 변환 검증](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html).

### 화면과 배포

밝은 회색 배경·청록색 강조, 날씨/카메라/목록 카드, 작은 화면의 세로 배치를 적용했습니다. 설정 메뉴는 기본적으로 접혀 있으며 왼쪽 메뉴(☰)에서 사용자 추가·준비물·날씨·장치 설정을 변경합니다. 실제 인증키 입력란은 제공하지 않습니다.

배포 ZIP에는 실행 코드·공식 지역 데이터·테스트·펌웨어·문서를 포함합니다. 실제 인증키·사용자 DB 및 등록 사진·YOLO 가중치·가상환경은 제외합니다. ZIP의 local_settings.py는 예제 키만 담고 있습니다. 기존 작업 폴더의 실제 설정과 사용자 데이터는 변경하지 않습니다.

```powershell
python scripts/package_release.py . ../CheckIT_MVP.zip
```

실물 인수 점검은 별도로 남아 있습니다: 실제 개인 물건의 인식률, 실제 웹캠 권한 거부·장치 제거·장시간 사용, Arduino 업로드와 LCD·버튼·전원. 상세 실행 결과와 한계는 VALIDATION.md를 참고하세요.

### 기상청 날씨·우산 자동 추가

1. [공공데이터포털의 기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)를 활용 신청하고 해당 서비스 인증키를 발급받습니다. 기상청 API허브의 별도 authKey와 혼용하지 않습니다.
2. `local_settings.py`의 `KMA_SERVICE_KEY = "여기에_일반_인증키_Decoding을_넣으세요"`에서 따옴표 안을 실제 인증키로 교체합니다. 또는 서버 실행 전에 `KMA_SERVICE_KEY` 환경 변수로 설정합니다(환경 변수 우선). 인증키 입력란은 이용자 화면에 표시하지 않으며 DB·검사 기록에도 저장하지 않습니다. 실제 키가 들어 있는 local_settings.py는 Git 및 배포 ZIP에서 제외하세요.
3. ‘지역 선택’에서 시·도 → 시·군·구 → 읍·면·동을 선택합니다. 기상청 격자는 자동으로 지정됩니다. 상세 동을 지정하지 않으려면 ‘대표 지점’을 선택할 수 있습니다. 대표 지점의 날씨가 행정구역 전체의 날씨를 뜻하지는 않습니다.
4. 비 판단 기준을 ‘현재 비’, ‘오늘 남은 시간 비 예보’, ‘현재 비 또는 오늘 비 예보’ 중 선택합니다. 예보 강수확률을 기준에 포함할지와 임계값도 설정할 수 있습니다.
5. ‘우산 자동 추가’를 켜고 설정을 저장합니다. 지역·기준은 사용자별로 저장합니다. 자동 추가를 꺼도 설정한 지역의 날씨는 조회할 수 있습니다.

지역 선택은 기상청 공식 참고자료의 전국 17개 시·도, 3,838개 지역·대표 지점 데이터를 사용합니다. `data/weather_regions.json`에 함께 배포하므로 지역 선택에 인터넷이나 인증키가 필요하지 않습니다. 자료 기준은 2026년 7월 격자 파일이며 2026-10-16 내려받은 9월 API 가이드에서 추출했습니다. 행정구역 변경 시 공식 자료로 갱신해야 합니다. 출처와 원본 ZIP 해시는 JSON 메타데이터에 기록했습니다.

기존 사용자 지정 격자는 ‘격자 직접 입력’에서 계속 사용할 수 있습니다. 운영자가 설정 파일 또는 환경 변수에 인증키를 한 번 설정하면 이용자는 지역을 선택해 사용합니다. 키를 변경한 뒤에는 서버를 다시 실행하고 날씨 새로고침을 누르세요.

초단기실황 `getUltraSrtNcst`의 PTY와 단기예보 `getVilageFcst`의 PTY·POP를 사용합니다. 현재 비·비/눈·빗방울 계열, 예보 비·비/눈·소나기가 해당하며 순수 눈만으로는 비 조건에 해당하지 않습니다. 강수확률 옵션을 켜면 오늘 남은 시간의 확률이 임계값 이상인 경우도 포함합니다. 과거 시간과 다음 날의 예보는 우산 판단에서 제외합니다.

발표 직후 지연을 피하기 위해 15분 여유를 두고 발표 시각을 선택합니다. 실황은 정시, 단기예보는 02·05·08·11·14·17·20·23시 발표를 선택하며 23시 발표에 당일 자료가 없으면 직전 발표를 확인합니다. 화면에 조회 시각과 사용한 발표 시각을 표시합니다.

카메라 위에 “오늘 15~17시 비 예보가 있어요. 우산도 잊지 마세요.”처럼 간략한 안내를 표시합니다. 연속된 예보 시간은 묶고 이미 지난 시간은 제외합니다. 강수형태에 비가 표시된 경우와 강수확률 기준에만 해당한 경우를 구분합니다. 현재 비가 관측되면 함께 안내하며, 현재 실황만 조회한 경우에는 오늘 예보를 조회하지 않았음을 명시합니다. 표시되는 시간은 실제 조회 자료에 따라 달라집니다.

- 날씨는 백그라운드에서 조회합니다. 성공 후 10분, 실패 후 1분 간격으로 다시 확인하며 ‘날씨 새로고침’으로 수동 조회할 수 있습니다.
- 자료 없음·불완전 응답·잘못된 지역/시각·인증 오류·네트워크 오류는 조회 실패로 안내합니다. 조회 실패를 ‘비 없음’으로 처리하지 않습니다. 두 종류를 함께 조회하는 기준에서 일부 조회가 실패해도 전체 판단은 실패로 안내합니다.
- 비 조건에 해당하면 오늘 검사 목록에 우산을 추가합니다. 기존 우산은 중복 추가하지 않습니다. 자동 추가 우산은 당일에만 유효하며 다음 날에는 새 조회 결과로 결정합니다.
- 오늘 제외한 우산은 새 검사·날씨 갱신·지역 변경에도 당일 다시 추가하지 않습니다. ‘오늘 복원’으로 되돌릴 수 있습니다. 우산을 삭제한 경우에도 당일 자동 재추가를 막습니다.
- 비 조건이 나중에 해제되거나 자동 추가를 꺼도 이미 추가한 당일 우산을 자동 삭제하지 않습니다. 필요하면 직접 제외·삭제하세요.
- 날씨로 임시 추가한 우산을 영구 목록에 두려면 준비물 관리에서 ‘우산 자동 인식’으로 직접 추가합니다.
- 사용자·날짜·조회 설정·인증키가 변경되면 이전 조회 결과를 새 목록에 적용하지 않습니다. 인증키가 없으면 설정 안내를 표시하고 사진·수동 확인은 계속 사용할 수 있습니다.

이번 단계의 API 응답 검증은 모의 응답으로 수행했습니다. 발급받은 실제 인증키와 지역 격자로 실서비스 조회를 추가 확인해야 합니다. 참고: [기상청 단기예보 설명](https://datawiki.kma.go.kr/doku.php?id=기상예보:날씨예보:단기예보).

### LCD 목록 전송과 재연결

- 오늘 검사 대상의 미완료 항목 중 목록 순서대로 앞의 2개를 표시합니다. 전체 목록은 2개로 제한하지 않습니다.
- 항목 확인 시 다음 미완료 항목으로 바꾸며 체크 해제·오늘 제외·복원·사용자 전환도 반영합니다.
- 전체 확인 시 `READY!` / `ALL CHECKED`, 검사 대상이 없으면 `NO ITEMS`를 표시합니다.
- 웹앱의 ‘LCD 전송 내용’에서 두 줄과 수신 확인 상태를 확인할 수 있습니다. 실제 LCD 화면을 센서로 읽은 결과는 아닙니다.
- 재연결 후 약 2초 부팅 대기가 끝나면 최신 화면과 상태를 자동으로 전송합니다. 확인 결과를 초기화하지 않습니다.
- 응답 시간 초과는 경고하며 ‘현재 상태 재전송’으로 다시 보낼 수 있습니다. 오래된 화면 번호의 ACK는 최신 화면 수신 확인으로 인정하지 않습니다.

**구형 펌웨어는 새 DISPLAY 명령을 지원하지 않습니다. 최신 `arduino/checkit.ino`를 한 번 업로드하세요. 실제 LCD를 사용하려면 `USE_LCD 1`로 변경합니다.** 이후 준비물 목록 수정 때는 다시 업로드하지 않습니다. 통신 상세는 [Arduino 화면 동기화 규약](arduino/PROTOCOL.md)을 참고하세요.

### 사용자별 준비물 관리와 저장

- 화면 상단에서 사용자를 선택합니다. 사이드바 ‘사용자 추가’에서 새 사용자를 만들 수 있습니다. 새 사용자는 기본 물병·책·우산 목록으로 시작합니다.
- 사이드바 ‘준비물 관리’에서 이름, LCD 영문 이름, 확인 방식을 입력해 준비물을 추가합니다. LCD 이름은 영문·숫자·공백·밑줄·하이픈 1~16자입니다.
- 자동 인식 선택은 현재 물병·책·우산에 제공하며 같은 종류를 중복 등록하지 않습니다. 임의의 준비물은 ‘직접 체크’로 추가할 수 있습니다. 등록만으로 YOLO가 새 물건을 학습하지 않습니다.
- ‘삭제’는 해당 사용자 목록에서 제거합니다. ‘오늘만 제외’는 목록을 보존하고 오늘 검사에서만 제외하며 ‘오늘 복원’으로 되돌릴 수 있습니다.
- 날짜 기준은 Asia/Seoul입니다. 다음 날에는 제외한 항목을 다시 포함하며 새 검사로 확인 결과를 초기화합니다. 같은 날 새 검사를 눌러도 오늘 제외는 유지됩니다.
- 사용자 전환 시 이전 확인 결과와 처리 중인 자동 인식 결과를 초기화합니다. 목록 수정 시 유지되는 항목의 확인 결과는 보존하고 삭제·제외된 항목의 확인은 제거합니다. 제외 후 복원한 항목은 다시 확인해야 합니다.
- AI 신뢰도와 검사 구역은 변경 시 사용자별로 저장합니다. 카메라 권한과 검사 확인 결과는 영구 저장하지 않습니다.

목록·설정은 로컬 `data/profiles.sqlite3`에 저장되어 앱을 재시작해도 유지됩니다. 이 파일은 사용자 데이터이므로 배포 ZIP이나 Git에 포함하지 않습니다. 백업 시 앱을 종료한 뒤 파일을 복사하세요. 별도의 데이터 경로는 `CHECKIT_PROFILE_DB` 환경 변수로 지정할 수 있습니다. 사용자 선택은 이 PC에서 사용하는 프로필 기능입니다.

`data/items.json`은 새 사용자 생성 시의 기본 목록입니다. 기존 사용자의 목록 변경은 웹앱에서 수행합니다. LCD 영문 이름은 저장 후 화면 전송에 사용합니다.

### 실시간 카메라 사용

실시간 영상과 사진 촬영은 같은 USB 카메라를 사용합니다. 브라우저 권한을 허용하면 이름에 `USB`가 포함된 카메라를 자동 선택하며, 여러 대라면 화면의 USB 카메라 목록에서 선택할 수 있습니다. USB 카메라가 없으면 내장 카메라로 대신 연결하지 않고 오류를 표시합니다. 장치 이름에 `USB`가 없는 외장 카메라는 현재 자동 선택 대상이 아닙니다.
사진 촬영(개인 물건 인식 시험 포함) 전에는 ‘카메라 사용’을 꺼서 실시간 영상의 장치 점유를 해제하세요. USB 장치를 변경하면 실시간 연결도 새 장치로 다시 생성됩니다.
연결 위젯은 주기 갱신 대상에서 제외하고 수신 상태만 0.5초마다 확인합니다. USB 카메라를 여는 동안 중복 연결을 시작하지 않도록 합니다.

1. requirements.txt를 다시 설치하고 앱을 실행합니다. 브라우저 카메라 권한을 허용하면 자동으로 연결합니다. 마이크는 사용하지 않습니다.
2. 영상의 노란 `CHECK AREA` 안에 물건을 놓습니다. ‘검사 구역 설정’에서 가로·세로 범위를 백분율로 조정합니다.
3. 탐지 박스 중심이 경계 안에 있는 종류만 반영합니다. 구역 안 박스는 녹색, 구역 밖 박스는 회색입니다.
4. 최소 3회·0.8초 이상 연속 탐지하면 확인합니다. 분석 간격이 1초를 넘거나 해당 종류가 보이지 않으면 연속 탐지를 다시 시작합니다.
5. ‘카메라 사용’을 해제하면 인식을 중지합니다. 확인 결과는 유지하며, 다시 켜면 재연결합니다.
6. 수동 해제한 종류는 성공적으로 분석한 영상에서 1초 이상 연속으로 보이지 않은 뒤 다시 안정적으로 탐지되어야 자동 확인합니다. 중지·오류·끊김은 부재로 간주하지 않습니다. 직접 체크하거나 새 검사로 초기화할 수도 있습니다.

사진 입력은 ‘사진으로 확인’에 유지합니다. 사진은 전체 이미지에서 즉시 확인하는 보조 입력이며 영상 검사 구역을 적용하지 않습니다. 수동 해제한 종류의 재확인 방지는 사진에도 적용합니다.

기본 연결은 같은 PC의 `http://localhost:8501` 또는 `http://127.0.0.1:8501`을 대상으로 하며 외부 ICE 서버를 사용하지 않습니다. 원격 접속은 HTTPS와 네트워크에 맞는 STUN/TURN 구성이 필요합니다. 카메라 권한 거부·미연결 시 사진이나 직접 체크를 사용할 수 있습니다. 영상은 파일로 기록하지 않습니다.

영상 콜백은 Streamlit 세션과 장치에 직접 접근하지 않습니다. 잠금으로 보호한 결과를 0.5초 주기의 화면 갱신에서 체크리스트와 통신에 반영합니다. 설정 변경·새 검사 때 이전 처리 중 결과는 버립니다.

구현 참고: [streamlit-webrtc 공식 저장소](https://github.com/whitphx/streamlit-webrtc).

## 사진 입력 안내

물병(bottle), 책(book), 우산(umbrella)을 사진으로 인식하고 준비물을 누적 확인합니다.
YOLO 결과는 실제 물품의 부재를 증명하지 않습니다. 항상 **미확인**으로 안내합니다.
사진 입력도 계속 지원합니다. 날씨 연동은 위 사용 안내를 참고하세요. 시간표는 현재 연동하지 않습니다.

## Windows 11 / VS Code 실행

Python 3.11(64비트)을 설치하고 ZIP을 압축 해제합니다. VS Code에서 **CheckIT_MVP** 폴더를 열고 PowerShell 터미널에서 실행하세요.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

기본 주소: http://localhost:8501 . 가상환경 활성화가 필요 없어 PowerShell 실행 정책을 변경하지 않아도 됩니다.
인터넷이 필요하고 PyTorch 설치에는 디스크 공간과 시간이 필요합니다. GPU 없이 CPU에서도 사용할 수 있습니다.
의존성은 호환 버전 범위로 명시했습니다. 모든 범위 내 조합을 검증한 것은 아닙니다.

## 시연 순서

1. 기본 **시뮬레이션** 모드로 열면 준비물 확인이 시작됩니다.
2. 이미지를 업로드하거나 카메라를 촬영하고 YOLO 분석 실행을 누릅니다.
3. 다른 사진을 분석하면 확인 기록이 누적됩니다. 중복 탐지는 확인 개수를 늘리지 않습니다.
4. 인식되지 않은 준비물은 체크박스로 직접 확인합니다. 완료 후에도 체크 해제가 가능합니다.
5. 모두 확인하면 자동으로 READY가 됩니다. 체크 해제 시 SCANNING으로 돌아갑니다.
6. 장치 작동 상태에서 LED, 서보, LCD 표시와 통신 기록을 확인합니다.
7. 새 검사를 누르면 현재 확인 기록과 결과가 초기화됩니다.

사진이나 모델 없이도 세 물품을 수동 확인하여 전체 상태 흐름을 시연할 수 있습니다.
시뮬레이션은 장치 동작 표시를 모사하며 YOLO 탐지 결과를 꾸며내지 않습니다.
자동 인식과 수동 확인은 기록에서 구분하며 JSON으로 다운로드할 수 있습니다.
하드웨어 시작 버튼의 중복 입력은 진행 중 확인을 지우지 않습니다. 웹앱의 새 검사는 확인 결과를 초기화합니다.

## YOLO와 사진 처리

첫 **분석 요청** 시 Ultralytics가 YOLO11n 가중치를 자동 다운로드합니다. 기본 경로는 `models/yolo11n.pt`이며 ZIP에는 포함하지 않습니다.
인터넷 다운로드에 실패하면 연결을 확인한 뒤 재시도하거나 공식 YOLO11n 가중치를 해당 경로에 놓으세요.
카메라 접근 권한을 허용해야 촬영할 수 있습니다. 카메라가 없으면 업로드를 사용하세요.
잘못된 이미지, 2,500만 픽셀을 넘는 사진, 모델/추론 실패는 안내 메시지로 표시합니다.
신뢰도 기준은 사이드바에서 조절합니다. 물품을 밝은 곳에서 크게 촬영하고 가리지 마세요.
사진은 앱에서 파일로 저장하지 않고 메모리에서 처리합니다. 모델만 디스크에 저장합니다.
사진에 여러 동일 물체가 있으면 박스는 각각 표시하고 체크리스트는 종류당 한 번만 확인합니다.
일부만 확인하면 SCANNING을 유지하고 모두 확인하면 자동으로 READY가 됩니다.

## 사진 분석 중 WinError 4551이 발생할 때

Windows 애플리케이션 제어 정책이 PyTorch의 DLL 로드를 차단한 오류입니다.
사진 형식이나 책 인식률 문제가 아니며 모델 추론이 시작되기 전에 발생합니다.
이벤트 뷰어의 `Microsoft-Windows-CodeIntegrity/Operational` 로그에서 차단 파일과 정책을 확인할 수 있습니다.
학교·회사 관리 PC는 관리자에게 해당 기록을 전달하고 승인된 실행 환경을 요청하세요.
Smart App Control은 개별 앱만 허용하는 예외 기능을 제공하지 않습니다.
보안 설정을 임의로 변경하거나 DLL 파일을 다른 사이트에서 받아 교체하지 마세요.
승인된 실행 환경이 준비될 때까지 수동 확인과 Arduino 시뮬레이션을 사용할 수 있습니다.
참고: https://support.microsoft.com/en-us/windows/what-is-smart-app-control-285ea03d-fa88-4d56-882e-6698afdb7003

## Arduino 연결 및 업로드

Arduino IDE에서 보드를 **Arduino Uno**, 포트를 실제 COM 포트로 선택합니다.
`arduino/checkit.ino`는 IDE에서 열 때 **checkit 폴더로 이동/생성** 제안을 승인하거나,
미리 `arduino/checkit/checkit.ino`로 복사해 열면 됩니다.
Servo 라이브러리(Arduino 공식)를 설치하세요. 현재 스케치는 LCD 사용을 위해 `USE_LCD 1`로 설정되어 있습니다.
LCD 없이 사용하려면 코드 첫 부분을 `#define USE_LCD 0`으로 변경하세요.
LCD 라이브러리는 Library Manager에서 **LiquidCrystal I2C (Frank de Brabander)**를 설치하세요.
기본 I2C 주소는 0x27입니다. 모듈이 0x3F이면 생성자와 연결 확인 주소를 모두 바꾸세요.
LCD는 ASCII 영어를 표시합니다. 부팅 시 LCD 주소 응답이 없으면 LCD 출력을 건너뜁니다.

| 부품 | UNO 연결 |
|---|---|
| 시작 버튼 | D2 ↔ 버튼 ↔ GND |
| 결과 확인 버튼 | D3 ↔ 버튼 ↔ GND |
| SG90 신호선 | D5 |
| 초록 LED | D6 → 220~330Ω 저항 → LED 양극, 음극 → GND |
| 빨간 LED | D7 → 220~330Ω 저항 → LED 양극, 음극 → GND |
| 소형 수동 피에조 부저 | D8 → +, GND → − |
| I2C LCD | SDA=A4, SCL=A5, VCC=5V, GND=GND |

버튼은 INPUT_PULLUP이므로 누르면 LOW입니다. 4핀 버튼은 내부로 이미 연결된 핀 쌍을 확인하세요.
SG90은 안정적인 **외부 정전압 5V 전원**으로 공급하고 UNO GND와 전원 GND를 공통 연결하세요.
외부 전원의 +5V를 UNO USB 5V와 무작정 병렬 연결하지 마세요. 서보 전류 부족은 UNO 재부팅 원인이 됩니다.
LED는 각각 직렬 저항을 사용합니다. 전류가 큰 부저는 D8에 직접 연결하지 말고 트랜지스터 드라이버를 사용하세요.
서보는 가벼운 CHECK/READY 안내판만 움직이며 출입문을 잠그는 장치가 아닙니다.

업로드 후 Arduino IDE의 시리얼 모니터를 닫고 웹앱에서 실제 Arduino 모드, COM 포트, 연결을 선택하세요.
UNO 재부팅을 위해 약 2초 동안 검사 버튼이 비활성화됩니다. 다른 프로그램이 포트를 점유하면 연결할 수 없습니다.
웹앱은 자동으로 확인을 시작하며 새 검사 버튼으로 초기화합니다. 실제 START/CHECK 버튼의 기존 통신은 유지하며 약 0.5초 간격으로 수신합니다.
실제 START 버튼은 검사 세션만 시작하며 웹캠 셔터를 자동 누르지는 않습니다.

## 통신과 상태

현재 웹앱의 정상 동기화는 `DISPLAY,번호,상태,첫째줄,둘째줄`과 `ACK,DISPLAY,번호`를 사용합니다. 아래 기존 상태 명령도 펌웨어에서 호환을 위해 유지합니다. 자세한 필드 검증과 예시는 [통신 규약](arduino/PROTOCOL.md)에 있습니다.

115200bps / ASCII / 줄바꿈 LF입니다.

| Python 상태 | 송신 | 장치 동작 |
|---|---|---|
| IDLE | RESET | CHECK(0°), LED 꺼짐 |
| SCANNING | SCAN | 빨간 LED 점멸, CHECK |
| MISSING | MISSING,n | 빨간 LED 켜짐, 진입 시 부저 250ms |
| READY | READY | 초록 LED 켜짐, READY(90°) |
| ERROR | ERROR | 빨간 LED 점멸, CHECK |

Arduino는 `START`, `CHECK` 버튼 이벤트와 `ACK,SCAN`, `ACK,MISSING`, `ACK,READY`,
`ACK,RESET`, `ACK,ERROR` 응답을 전송합니다. 잘못된 명령은 `ERR,COMMAND`로 응답합니다.
부저는 MISSING에 새로 진입할 때만 울립니다. RESET/SCAN 뒤 다시 MISSING이면 다시 울립니다.
응답이 4초 이상 지연되면 경고하고 ‘현재 상태 재전송’으로 다시 보낼 수 있습니다.
전송/수신 오류나 케이블 분리 시 포트를 닫고 오류를 표시합니다. 재연결 후 부팅이 끝나면 최신 화면을 자동 동기화합니다. 필요하면 현재 상태 재전송을 누르세요.
사진 분석 오류의 ERROR는 장치 알림 상태입니다. 체크리스트는 SCANNING을 유지하여 다시 분석하거나 수동 확인할 수 있습니다.
장치 표시와 체크리스트 상태를 함께 확인하세요. ACK는 명령 수신 확인이며 실제 모터 위치 센서 확인이 아닙니다.

세션 상태에 컨트롤러를 한 번 보관해 일반적인 Streamlit 재실행 때 포트를 재개방하지 않습니다.
포트 변경/모드 변경 시 기존 연결을 닫습니다. 한 PC에서 하드웨어를 제어하는 브라우저 탭은 하나만 사용하세요.
브라우저 새로고침/연결 종료 후 자동 정리 시점은 Streamlit 세션 수명에 달려 있으므로 새로고침 전에 연결 해제를 누르세요.
다른 탭이 포트를 점유하면 연결 오류로 안내합니다. 사진/확인 기록은 영구 저장하지 않으며 새 세션에서는 초기화됩니다.

## 코드 읽는 순서와 테스트

`data/items.json` → `checklist.py` → `detector.py` → `arduino_controller.py` → `app.py` 순서로 읽으면 됩니다.
`config.py`에서 모델 경로와 통신 속도/응답 제한을 설정합니다.
준비물을 추가할 때는 JSON에 COCO 영문 클래스와 한국어 이름을 넣으세요. 기본 모델이 지원하지 않는 물체는 별도 학습이 필요합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q .
```

실제 실행 결과는 동봉한 `VALIDATION.md`에 기록합니다.
실물 검증이 필요한 항목: 웹캠 권한과 촬영, 실제 YOLO 모델 다운로드 및 사진 추론 정확도,
UNO 업로드/버튼/USB 통신, 실제 LED·부저·SG90 동작, LCD 주소 및 실제 미연결 상황.
이 항목들은 모의 통신 테스트만으로 검증됐다고 주장하지 않습니다.

공식 참고 문서: [YOLO11](https://docs.ultralytics.com/models/yolo11/),
[Streamlit fragments](https://docs.streamlit.io/develop/concepts/architecture/fragments).
Ultralytics 및 사전 학습 가중치의 라이선스(AGPL-3.0 또는 상용 조건)는 외부 배포 전에 확인하세요.
# YOLO 자동 인식 종류 확장

카메라 화면 전체를 인식 범위로 사용합니다. 검사 구역 설정·초기화와 구역 테두리는 제거했으며, 이전에 저장한 구역 범위는 적용하지 않습니다. 개인 물건 시험도 사진 전체를 사용합니다. 자동 체크의 연속 탐지 조건은 유지합니다.


준비물 추가의 확인 방식에서 기본 YOLO 모델이 지원하는 COCO 80종 중 사람(person)을 제외한 79종을 선택할 수 있습니다. 사진·실시간 영상 분석 모두 사람 탐지를 제외합니다. 백팩·핸드백·휴대폰·노트북·마우스·키보드·컵·가위·칫솔 등이 포함됩니다. 표시된 영문 이름이 실제 모델의 클래스명입니다. 기본 준비물 목록은 기존 물병·책·우산을 유지합니다.

이는 새 학습이 아니라 기존 모델의 지원 종류를 준비물에 연결하는 변경입니다. 지갑·열쇠 등 모델에 없는 종류는 개인 사진 비교나 직접 체크를 사용합니다. 같은 종류의 개별 물건은 구별하지 않으며, 인식 성능은 실제 카메라에서 확인해야 합니다.
