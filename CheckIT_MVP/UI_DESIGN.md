# CheckIT 웹앱 화면 설계

진행 단계: 9/9 — 개인 물건·화면·배포 구현

이 문서는 목표 화면과 단계별 적용 결과를 정의합니다. 현재 app.py는 실시간 영상·사진 입력, 사용자별 목록, LCD 전송, 날씨·우산 추가, 개인 물건 사진 비교를 지원합니다. 실제 물건의 인식률과 Arduino 실물 검증은 별도로 남습니다.

## 메인 화면

가장 중요한 작업은 물건을 검사 구역에 놓고 확인 여부를 보는 것입니다. 데스크톱에서는 영상과 체크리스트를 나란히 배치합니다. 사용자 선택은 상단, 자주 사용하지 않는 설정은 사이드바에 둡니다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 🎒 CheckIT     외출 준비를 한눈에             사용자 [선택 ▾] │
│ 오늘 날짜 · Asia/Seoul                                        │
├──────────────────────────────────────────────────────────────┤
│ 오늘의 준비 · 1/3 확인             날씨: 조회 전 / 지역 설정   │
├────────────────────────────────────┬─────────────────────────┤
│ 준비물 카메라                       │ 오늘의 준비물           │
│ ● 인식 중                          │ 1/3 확인 · 진행률        │
│ ┌────────────────────────────────┐ │                         │
│ │                                │ │ □ 물병       미확인     │
│ │   ┌── 검사 구역 ──────────┐     │ │ ☑ 책(취소선) 자동 확인  │
│ │   │ 여기에 물건을 놓으세요 │     │ │ □ 우산       미확인     │
│ │   └──────────────────────┘     │ │                         │
│ └────────────────────────────────┘ │ [준비물 관리]           │
│ [인식 중지] [검사 구역 설정]        │ [오늘 제외한 항목 ▾]    │
│ 사진으로 확인 ▾                    │                         │
├────────────────────────────────────┴─────────────────────────┤
│ 물병과 우산을 확인해주세요.                       [새 검사]  │
│ LCD: 연결됨 · 표시 내용 [BOTTLE / UMBRELLA]                   │
└──────────────────────────────────────────────────────────────┘
```

- 카메라와 목록의 너비 비율은 약 3:2로 시작합니다.
- 실제 체크박스 옆에 이름을 배치하고 완료된 이름에는 취소선을 적용합니다.
- 확인 출처는 작은 보조 문구로 표시합니다. 미확인 항목에도 수동 체크를 허용합니다.
- 준비물 순서를 유지합니다. 확인할 때마다 행을 이동시키지 않습니다.
- 완료 시 하단 안내를 “모든 준비물을 확인했어요. 출발 준비 완료!”로 바꿉니다.
- LCD 연결 여부와 관계없이 웹앱의 확인 기능을 사용할 수 있게 합니다.
- 사진 업로드는 카메라 아래의 접힌 보조 영역에 둡니다.

## 화면 크기와 시각 스타일

| 요소 | 기준 |
|---|---|
| 배경 | 밝은 회색 #F6F8FA |
| 카드 | 흰색, 옅은 테두리, 모서리 12px |
| 기본 글자 | 짙은 회색 #172B4D |
| 주요 버튼 | 짙은 청록 #0F766E, 흰색 글자 |
| 완료 | 녹색 계열과 체크 아이콘·완료 문구 |
| 주의·실패 | 주황/빨강 계열과 원인·복구 문구 |
| 글꼴 | 시스템 한글 글꼴, 본문 16px 기준 |
| 여백 | 요소 사이 8/16/24px, 카드 내부 20~24px |
| 조작 영역 | 버튼과 체크박스 행 높이 최소 44px |

좁은 화면에서는 상단 요약 → 카메라 → 체크리스트 → 장치 상태 순서로 한 열에 배치합니다. 가로 스크롤을 만들지 않습니다. 사용자 선택과 설정은 접을 수 있게 합니다. 실제 반응형 표시와 색 대비는 브라우저에서 확인합니다.

상태는 색상만으로 전달하지 않습니다. 체크박스에는 준비물 이름을 접근 가능한 라벨로 연결하고 키보드로 조작할 수 있게 합니다. 자동 확인이 발생해도 입력 중인 항목의 포커스를 이동시키지 않습니다.

## 카메라와 검사 상태

| 상황 | 표시 문구와 동작 |
|---|---|
| 권한 요청 전 | “카메라를 허용하면 자동으로 확인을 시작합니다.” |
| 카메라 준비 중 | “카메라를 연결하고 있어요.”, 중복 요청 방지 |
| 인식 중 | “인식 중”, 검사 구역 경계와 중지 버튼 표시 |
| 인식 중지 | “인식이 중지됐어요.”, 기존 확인 유지, 재개 버튼 표시 |
| 권한 거부·카메라 없음 | 원인 안내와 다시 시도·사진 업로드·수동 확인 제공 |
| 분석 실패 | “자동 확인에 실패했어요. 다시 시도하거나 직접 체크해주세요.”, 기존 확인 유지 |
| 미확인 항목 있음 | 남은 항목 안내. 물건이 없다고 단정하지 않음 |
| 전체 확인 | 준비 완료 안내. 체크 해제와 새 검사 가능 |
| 검사 대상 0개 | “오늘 검사할 준비물이 없어요.”, 준비물 관리 안내 |

카메라 권한 허용과 영상 준비 후 자동으로 검사를 시작합니다. 별도의 검사 시작·결과 확인 버튼은 목표 화면에서 제거합니다. ‘인식 중지’는 확인 결과를 지우지 않으며 ‘새 검사’만 확인 결과를 초기화합니다. 새 검사에는 초기화 의미를 설명하는 보조 문구를 붙입니다.

새 검사는 오늘의 목록과 당일 제외 상태를 유지합니다. 사용자 전환은 해당 사용자의 목록과 설정을 불러오고 이전 사용자의 검사 결과가 섞이지 않게 초기화합니다. 날짜 기준은 Asia/Seoul입니다.

## 설정과 관리 영역

| 영역 | 내용 | 구현 단계 |
|---|---|---|
| 메인 체크리스트 | 체크·해제, 확인 출처, 진행률, 새 검사 | 3 |
| 검사 구역 설정 | 영상 위 구역 표시, 위치·크기 조정, 적용 | 4 |
| 준비물 관리 | 추가·삭제, 오늘만 제외·복원, 한글명·LCD 영문명 | 5 |
| 사용자 | 선택, 사용자별 목록과 설정 저장 | 5 |
| 장치 설정 | 시뮬레이션/실제 장치, COM 포트, 연결·해제 | 6 |
| 장치 상태 | 실제 연결 여부와 마지막 전송 내용, 통신 오류·재시도 | 6 |
| 날씨 설정 | 지역, 우산 자동 추가, 비 판단 기준 | 7 |
| 개인 물건 | 이름·사진 등록, 인식 시험, 삭제 | 8 |

통신 로그·탐지 신뢰도·검사 기록 다운로드는 접힌 상세 영역에 둡니다. 시뮬레이션과 실제 장치 상태는 명확하게 구분하며 전송 예정 내용과 장치 수신 확인을 혼동하지 않게 표시합니다.

## 날씨 표시

- 미설정: “날씨 지역을 설정해주세요.”
- 조회 중: “날씨를 확인하고 있어요.”
- 우산 조건 충족: “비 예보가 있어 우산을 추가했어요.”
- 조건 미충족: 조회 시각과 해당 조건에 맞는 안내 표시
- 실패: “날씨를 불러오지 못했어요. 우산 필요 여부를 직접 확인해주세요.”와 재시도
- 당일 제외: “우산은 오늘 검사에서 제외했어요.”, 갱신 시 자동 복원하지 않음

연동 전에는 날씨 정보를 꾸며 표시하지 않습니다. 조회 실패를 맑음이나 비 없음으로 표시하지 않습니다.

## 단계별 적용과 확인 기준

3단계에서는 현재 사진 입력을 유지하면서 메인 배치, 체크박스·취소선, 자동 완료와 해제, 빈 목록 표시부터 구현합니다. 4단계에서 사진 입력을 보조 영역으로 옮기고 실시간 카메라를 주 입력으로 연결합니다. 사용자·날씨 등은 해당 기능이 구현된 단계에 활성화합니다.

화면 확인 기준:

- 카메라와 체크리스트를 동시에 확인할 수 있음
- 수동 체크·자동 확인이 같은 표시와 진행률에 반영됨
- 완료 후 체크 해제 시 즉시 미확인 화면으로 돌아감
- 구역 밖 물건, 일시적 탐지 실패, 카메라 중지가 완료 상태를 임의로 해제하지 않음
- 빈 목록과 전체 완료를 구분함
- 카메라·날씨·장치 오류가 서로 구분되고 다음 행동을 안내함
- 모바일에서 모든 조작이 보이며 키보드로 체크·해제 가능

이 단계는 화면 구조와 동작 설계입니다. 브라우저 시각 검증과 실제 기능 구현은 이후 단계에서 수행합니다.

## 3단계 적용 결과

카메라와 체크리스트를 3:2로 배치하고 체크박스·취소선·진행률, 자동 완료와 해제, 새 검사, 빈 목록을 구현했습니다. 장치 미연결 상태에서도 체크할 수 있습니다. EMPTY 상태는 현재 펌웨어에 RESET으로 전송합니다. LCD의 NO ITEMS 출력은 6단계에서 구현합니다.

## 4단계 적용 결과

카메라를 기본 입력으로 두고 사진 입력은 접힌 보조 영역으로 옮겼습니다. 카메라 사용 체크박스로 중지·재개하며 구역은 가로·세로 범위 슬라이더로 조정합니다. 영상에 구역 경계와 탐지 박스를 표시합니다. 박스 중심 기준, 최소 3회·0.8초 연속 인식, 1초 분석 공백 시 연속 기준 초기화, 수동 해제 후 1초 연속 부재 후 재인식을 적용했습니다. 오류·중지·설정 변경은 확인 결과를 지우지 않으며 오래된 자동 결과는 폐기합니다.

## 5단계 적용 결과

상단에 사용자 선택, 사이드바에 사용자 추가와 준비물 관리 영역을 추가했습니다. 준비물별 오늘 제외·복원과 삭제를 제공하고, 제외한 항목은 체크리스트 아래에 안내합니다. 사용자별 신뢰도·검사 구역을 저장합니다. 사용자 전환·날짜 변경 시 확인을 초기화하고 같은 사용자의 목록 수정 시 유지되는 확인은 보존합니다. 임의 준비물은 직접 체크로 등록하며 LCD 표시명도 미리 저장합니다. 저장소는 로컬 SQLite입니다.

## 6단계 적용 결과

체크리스트 아래에 LCD 전송 두 줄과 수신 확인 상태를 표시합니다. 완료·해제·목록 변경 때 갱신하며 재연결 시 최신 화면을 자동 동기화합니다. 실제 화면을 측정한 결과와 혼동하지 않도록 ‘LCD 전송 내용’으로 표기합니다. 통신 오류와 재전송은 기존 상세 영역에서 안내합니다.

## 7단계 적용 결과

카메라 위에 날씨 조회·실패·우산 조건 안내와 새로고침 버튼을 배치했습니다. 사이드바에서 지역, 자동 추가, 현재/예보 기준과 강수확률을 설정합니다. 인증키 입력란은 화면에서 제거하고 운영자 설정 파일 또는 환경 변수에서 읽습니다. 조회 중에도 체크 조작을 계속할 수 있으며 조회 실패는 비 없음과 구분합니다. 자동 추가한 우산도 기존 목록과 LCD 전송 내용에 함께 반영합니다.

지역은 시·도 → 시·군·구 → 읍·면·동 선택을 기본으로 합니다. 기상청 격자 좌표는 내부에서 자동 지정하며 사용자별 지역 코드와 함께 저장합니다. 상위 지역을 바꾸면 하위 선택을 초기화하고 선택을 완료하기 전에는 저장하지 않습니다. 대표 지점 선택과 기존 사용자용 격자 직접 입력도 제공합니다. 지역 데이터는 앱에 포함해 외부 지역 서버 장애와 관계없이 선택할 수 있습니다.

날씨 요약에는 실제 비 예보 시간을 묶어 “오늘 15~17시 비 예보가 있어요. 우산도 잊지 마세요.”로 표시합니다. 확률만 높은 경우에는 강수확률 안내로 구분하고, 현재 관측·예보 미조회·지난 시간·날짜 변경도 별도로 표현합니다. 우산을 오늘 제외했어도 날씨 요약은 계속 표시합니다.

## 8단계 적용 결과

메인 화면 아래에 개인 물건 등록·관리 영역을 추가했습니다. 여러 등록 사진의 미리보기·추가·삭제, 검사 장면 비교 시험, 시험 통과 후 자동 확인 켜기·끄기를 제공합니다. 사진 변경 후에는 다시 시험해야 하며 물건 삭제 시 사진도 삭제합니다. 등록과 시험용 사진의 저장 여부를 각 흐름에서 안내합니다.

## 9단계 적용 결과

밝은 배경과 청록색 강조, 날씨·카메라·체크리스트 카드, 손가락으로 누르기 쉬운 체크·버튼 크기를 적용했습니다. 설정 메뉴는 기본 접힘 상태로 두고 상단에 메뉴 위치를 안내합니다. 작은 화면에서는 영상과 목록을 세로로 배치합니다. 상세 통신·탐지 정보는 접힌 영역으로 유지합니다. 배포는 허용 파일 목록으로 생성해 실제 인증키와 사용자 DB·사진이 포함되지 않도록 합니다.
